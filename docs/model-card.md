# Model card — jeva (MiniCPM5-2B-WebDecider)

## Summary

| | |
|---|---|
| **Model** | jeva — a browser-agent decision model |
| **Base** | [`openbmb/MiniCPM5-2B`](https://modelscope.cn/models/OpenBMB/MiniCPM5-2B) (2.5B total, 2.0B non-embedding, `LlamaForCausalLM`, 42 layers, GQA 16/2) |
| **Released** | 2026-09-23 |
| **Method** | LoRA SFT (r=16, α=32, 1 epoch, 10,686 examples) then **merged into the base weights** |
| **Context** | 4,096 tokens is plenty; the prompt is 550–1,100 tokens, the answer ~25 |
| **License** | Apache-2.0 (same as the base) |
| **Output** | one JSON action: `{"operation", "target", "text"}` |

## Intended use

Inner-loop decision making for browser automation: which control to act on, what to type, and when
to stop. Designed to run alongside an executor that owns element resolution, freshness checks and
retries.

**Primary uses:** form filling, filter/sort selection, search submission, autocomplete picking,
recognising "goal satisfied" and "blocked by a challenge".

**Out of scope:** acting on the browser, multi-step widgets, file uploads, scrolling, general
chat, anything requiring selectors or coordinates to be produced.

## Training data

10,686 `(state, action)` pairs from 2,600 tasks, generated by driving real Chrome with a
deterministic solver. No human labels, no teacher model. A trajectory was kept only when the
environment verified the task succeeded — see [pipeline.md](pipeline.md).

Three sites were used, with **different label vocabularies and layouts**. `site3` was held out
entirely. Training included the first two sites only.

## Evaluation

**Method.** Each task is created from a randomised initial page state, executed step by step in
real Chrome with the model as the only decision maker, then judged by reading the resulting page
state (submitted field values are echoed into the result URL). The model's own `DONE` claim is
never trusted.

| Suite | Tasks | jeva | MiniCPM5-2B (base) | Bonsai-27B (zero-shot) |
|---|---|---|---|---|
| `site1` | 100 | **100%** | 10% | 92.5% (40 tasks) |
| `site2` | 40 | **100%** | — | — |
| `site3` (held out) | 40 | **100%** | — | — |
| live `httpbin.org/forms/post` | 4 runs | **4/4** all criteria | — | — |

Subsets where the page pre-fills nothing, so the model must do every step itself

against 18 invalid target indices for the base model.

## Calibration

jeva does **not** return probabilities — it returns an action. Confidence is therefore not
available the way it is for a classifier, and the model's `DONE` / `BLOCKED` output should be
confirmed by whatever verifier the caller already has. This is a deliberate trade: the model was
built to drive a loop, not to score items.

## Limitations

- Narrow action space (no `SCROLL`, no uploads, no multi-step dropdowns).
- Trained on form-shaped flows; off-distribution behaviour is not characterised.
- Prompt- and format-sensitive: the system prompt, the operation descriptions, and the state
  layout are part of the model. Use `jeva.prompt` / `jeva.render` rather than re-deriving them.
- Evaluated on three synthetic sites, in real Chrome, not on production websites.
- The Bonsai-27B baseline rests on 10 tasks and is indicative only.

## Ethical and licensing notes

- Base model and this derivative are Apache-2.0; the base is credited in the README.
- The training set contains no personal data: task instances are generated from fixed word lists
  (city names, dates, a few names and topics), and the pages are local fixtures.
- Because the model only emits indices into a caller-supplied observation, it cannot itself
  produce code that runs in a page; the authority to act remains with the executor.
